How to Talk to a Computer

Using AI to write code is a powerful skill — but it works best when you know the language you're asking it to speak. Here's how to get more out of AI tools and why learning syntax makes you a better prompter.

What is Vibe Coding?

Vibe coding means describing what you want in plain language and letting an AI tool (ChatGPT, Claude, Copilot, etc.) write the code for you. Instead of knowing every syntax rule by heart, you describe the idea — "I want 50 circles scattered randomly across the canvas, each a random size between 20 and 80 pixels" — and the AI translates it into working code.

This isn't cheating. It's a real workflow used by professional developers. The key is that it's a conversation, not a vending machine. You describe, it writes, you test, you refine. The quality of the output depends almost entirely on the quality of your description.

How a Computer Thinks

Before you can talk to a computer effectively — with AI or without — it helps to understand how a computer actually reads instructions. Unlike a person, a computer has no context, no intuition, and no ability to fill in gaps. It does exactly what you say, in exactly the order you say it, one step at a time.

That means a task that feels simple to a human often needs to be broken into several smaller, more explicit steps. "Draw a pink circle in the middle of the canvas" sounds straightforward, but a computer needs each part spelled out:

  1. Set the fill color to pink
  2. Turn off the stroke (or set a stroke color)
  3. Calculate the center of the canvas
  4. Decide on a diameter
  5. Call the function that draws a circle at those coordinates with that size

Miss a step, or put them in the wrong order, and you get something wrong — or nothing at all. This isn't a flaw in how computers work; it's the entire point. Computers are precise because they never assume.

Syntax is the rulebook that makes this possible. Every programming language has a specific way of writing instructions — where the parentheses go, what order the arguments come in, which words mean what. Syntax isn't arbitrary; it's the grammar that removes ambiguity. circle(x, y, diameter) means something exact. circle(diameter, y, x) means something different. The computer can't tell which one you "meant."

When you use an AI tool to generate code, you're essentially translating your human-language description into this step-by-step, syntax-precise form. The better you understand the steps involved and the rules of the language, the better you can check whether the translation is right.

Why Syntax Still Matters

You might wonder: if AI writes the code, why learn the syntax at all? There are three reasons it still matters deeply:

  • You need vocabulary to ask specific questions. If you don't know that ditherImage() exists, you'll ask for something vague like "make the image look grainy" — and get unpredictable results. Knowing the function name means you can ask for exactly what you want.
  • You need to recognize when the AI is wrong. AI tools hallucinate — they confidently write code using functions that don't exist, parameters in the wrong order, or logic that looks right but breaks at runtime. If you can't read the code at all, you have no way to catch these errors.
  • You need to debug when things don't work. AI can generate the starting point, but when something breaks — and it will break — you're the one reading the error message and figuring out what to fix. That requires understanding what the code is trying to do.

The Vocabulary Loop

Learning syntax and vibe coding aren't opposites — they reinforce each other. The more you understand, the better your prompts. The better your prompts, the more you can accomplish. The more you accomplish, the more you learn from reading the output.

Vague vs. Specific Prompts

The difference between a useful AI response and a useless one usually comes down to specificity. Here are examples of the same request at different levels of precision:

Too vague
"Make my sketch look more interesting."
Specific
"I have a p5.riso sketch with a fluorescent pink Riso layer. Add a for loop that draws 40 circles at random positions, with sizes between 20 and 80 pixels, using pink.fill(255) and pink.circle()."
Too vague
"Add a way to export the file."
Specific
"Add a keyReleased() function that calls exportRiso() when I press 'e', and calls redraw() when I press the space bar."
Too vague
"Make the image look like a RISO print."
Specific
"Use ditherImage(img, 'atkinson') to convert my loaded image, then draw the result to a blue Riso layer using blue.image() at position (0, 0), sized to fill the canvas."

When AI Gets It Wrong

AI tools make mistakes in specific, recognizable ways. Knowing these patterns helps you catch them:

  • Hallucinated functions. The AI might write pink.dither(img) or riso.export() — functions that sound right but don't exist in p5.riso. If you get a "X is not a function" error, check the actual p5.riso docs. The Glossary on this site lists every real function.
  • Wrong argument order. text(str, x, y) and rect(x, y, w, h) have specific argument orders. AI sometimes swaps them. If shapes appear in the wrong place or nothing renders, check that the arguments match the reference.
  • Missing p5.riso structure. AI trained on general p5.js code often forgets to include clearRiso() and drawRiso(), or draws shapes to the main canvas instead of to a Riso layer. If your output is all one color or looks like normal p5.js, this is usually why.
  • Confidently wrong explanations. The AI will explain its broken code as if it's correct. Don't trust the explanation — test the code and look at what actually happens.

Practical Prompt Patterns

A few templates that consistently get useful results for p5.riso work:

Setting context "I'm working in p5.js with the p5.riso library. My sketch uses a canvas of 825×1275 pixels at pixelDensity(1). I have two Riso layers: let pink = new Riso('fluorescentpink') and let blue = new Riso('blue'). My draw() function calls clearRiso() at the start and drawRiso() at the end."
Asking for a specific feature "Add [specific thing] using [specific function or approach]. It should go inside [setup / draw / keyReleased / etc.]. The result should [describe what you expect to see]."
Debugging with an error "My p5.riso sketch is throwing this error: [paste exact error message]. Here is the relevant code: [paste the function or block]. What's wrong and how do I fix it?"
Asking for an explanation "Explain what this line does in plain English: [paste line of code]. I know that [what you already understand] but I don't understand [specific thing]."

The Bottom Line

Vibe coding lowers the barrier to getting something on screen quickly. But the ceiling of what you can do — and how reliably you can do it — rises with every piece of syntax you learn. Treat the AI as a collaborator that knows a lot of code but needs you to direct it. The more clearly you can describe what you want, the better the collaboration gets.

Use the reference pages on this site to build your vocabulary. When you learn a new function, try prompting the AI to use it in a specific way. Then read the output and see if it matches what you expected.
