09

API Data

Pokémon base stats fetched live from the PokéAPI drive grid density, shape size, and rotation. Press 1–5 to switch Pokémon.

How it works

loadJSON() fetches any URL that returns JSON and automatically parses it into a JavaScript object. No extra libraries needed — p5 handles the request and the parsing. Each Pokémon's stats then map directly to visual parameters: speed controls grid density, attack controls circle size, defense controls square size, and HP controls rotation angle.

Step 1: fetch the data in preload()

let pokemon = null;

function preload() {
  // p5 waits here until the request finishes before running setup()
  pokemon = loadJSON("https://pokeapi.co/api/v2/pokemon/bulbasaur");
}

preload() is p5's built-in loading phase — it runs before setup() and blocks until every loadJSON(), loadImage(), or loadTable() call inside it completes. By the time your code reaches setup(), pokemon is fully loaded.

Step 2: understand the JSON structure

The PokéAPI returns a large JSON object. The part we care about looks like this:

{
  "name": "bulbasaur",
  "stats": [
    { "base_stat": 45, "stat": { "name": "hp" } },
    { "base_stat": 49, "stat": { "name": "attack" } },
    { "base_stat": 49, "stat": { "name": "defense" } },
    { "base_stat": 90, "stat": { "name": "speed" } }
  ]
}

pokemon.name is a string. pokemon.stats is an array of objects. Each object has two keys: base_stat (a number) and stat (another object with a name field). You navigate nested objects with dot notation, just like any other JavaScript object.

Step 3: extract values with a helper function

function getStat(name) {
  for (let s of pokemon.stats) {
    if (s.stat.name === name) return s.base_stat;
  }
  return 50; // fallback
}

// Usage:
let attack = getStat("attack");  // 49 for bulbasaur

Because stats are stored in an array (not a named object), we can't just write pokemon.stats.attack. We loop through the array and check each element's stat.name field. When we find a match, we return the base_stat. This is a common real-world pattern when working with APIs.

Step 4: map stat values to visual parameters

let cols     = floor(map(speed,   5, 180,  3, 10));
let pinkSize = map(attack,  5, 190,  8, 56);
let blueSize = map(defense, 5, 230,  6, 48);
let angle    = map(hp,      1, 255,  0, HALF_PI);

map() converts a value from one range to another. The stat ranges (5–180, 5–190, etc.) come from the actual min/max values in the PokéAPI. A Pokémon with speed 180 gets 10 grid columns; one with speed 5 gets 3. This is the same technique from Demo 07 — the stat becomes the data, and the visual parameters follow.

Step 5: draw directly to Riso layers

// Pink layer: grid of circles
pink.noStroke();
pink.fill(220);  // opacity 220/255
for (let c = 0; c < cols; c++) {
  for (let r = 0; r < cols; r++) {
    pink.circle((c + 0.5) * cellW, (r + 0.5) * cellH, pinkSize);
  }
}

// Blue layer: offset grid of rotated squares
blue.rectMode(CENTER);
for (let c = 0; c < cols; c++) {
  for (let r = 0; r < cols; r++) {
    blue.push();
    blue.translate((c + 1) * cellW, (r + 1) * cellH);
    blue.rotate(angle);
    blue.rect(0, 0, blueSize, blueSize);
    blue.pop();
  }
}

Riso layers (pink, blue) are graphics buffers — you can call drawing methods directly on them. push() and pop() save and restore the transformation state, so each square can be rotated around its own center without affecting neighboring squares. The offset grid (blue squares offset by half a cell) is a classic two-color RISO registration pattern.

Step 6: reload data with a callback

// When used outside preload(), loadJSON() needs a callback
loadJSON(
  "https://pokeapi.co/api/v2/pokemon/" + names[idx],
  function(data) {   // runs when the request finishes
    pokemon = data;
    redraw();
  }
);

Outside of preload(), loadJSON() is asynchronous — it starts the request and immediately moves on. The callback function runs when the data arrives, possibly seconds later. This is why we set loading = true first and show a "fetching..." message: the canvas needs to communicate what's happening while we wait.

The five Pokémon compared

  • Bulbasaur (hp:45 atk:49 def:49 spd:45) — slow, small, gentle rotation
  • Snorlax (hp:160 atk:110 def:65 spd:30) — sparse grid, large circles, heavy rotation
  • Jolteon (hp:65 atk:65 def:60 spd:130) — dense grid, medium shapes
  • Mewtwo (hp:106 atk:110 def:90 spd:130) — dense grid, large shapes, strong rotation
  • Dragonite (hp:91 atk:134 def:95 spd:80) — medium density, biggest circles

Same code, same two Riso colors — but each dataset produces a structurally different print. That's the core idea: the data is the design.
