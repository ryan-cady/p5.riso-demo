Debugging

How to find and fix problems in your sketch — opening the console, reading error messages, and common p5.js and p5.riso mistakes.

The Browser Console

The console is your most important debugging tool. It shows error messages, warnings, and anything you print with console.log(). Open it with:

  • Mac: Cmd + Option + J
  • Windows / Linux: F12, then click the Console tab
  • Any browser: right-click anywhere on the page → Inspect → Console tab

When your sketch isn't working, open the console first. The error message will usually tell you exactly what's wrong and which line to look at.

console.log()

Print any value to the console to see what's actually inside a variable. Indispensable for checking data, loop counts, and positions: 

let x = random(width);
console.log(x); // prints the actual number to the console

// Log multiple values at once:
console.log("x:", x, "y:", y);

// Inside a loop — see every value:
for (let i = 0; i < data.length; i++) {
  console.log(i, data[i]);
}

Remove or comment out console.log() calls when you're done debugging — logging inside draw() runs 60 times per second and can slow your sketch.

p5.js also provides print() as a shorthand that does exactly the same thing: 

print(x);         // same as console.log(x)
print("x:", x);   // same as console.log("x:", x)

Both work identically — use whichever feels more natural. print() is a bit shorter; console.log() is more standard JavaScript.

Common p5.js Errors

"X is not defined"

A variable or function is being used before it's declared, or declared in the wrong scope. Variables declared inside setup() aren't visible in draw() — declare them at the top of the file instead. 

// ✗ wrong — img is local to preload(), invisible in draw()
function preload() {
  let img = loadImage("photo.jpg");
}

// ✓ correct — declared at the top, accessible everywhere
let img;
function preload() {
  img = loadImage("photo.jpg");
}

Blank canvas / nothing appears

Several causes:

  • background() covers your shapes — move background() to the top of draw(), before drawing anything
  • fill and stroke are both off — check that you have fill() or stroke() set
  • Shapes are drawn off-canvas — log your x/y values and check they're within width and height
  • draw() never ran — if you called noLoop() before drawing anything, call redraw() to trigger one frame

Image doesn't load

Almost always a path problem or a missing preload(). Check: 

// ✗ wrong — images must be loaded in preload(), not setup()
function setup() {
  img = loadImage("photo.jpg"); // won't be ready in time
}

// ✓ correct
function preload() {
  img = loadImage("photo.jpg");
}

// ✗ wrong path — file is in an images/ folder but path is wrong
img = loadImage("photo.jpg");

// ✓ correct path
img = loadImage("images/photo.jpg");

If you're using Live Server locally, the path is relative to your HTML file. In the p5 web editor, just use the filename with no path.

"Cannot read properties of undefined"

You're trying to access a property on something that doesn't exist yet — usually because a variable hasn't been assigned, or an array index is out of bounds. 

// ✗ if data[5] doesn't exist, data[5].name will crash
let name = data[5].name;

// ✓ check the length first
console.log(data.length); // make sure index 5 exists
console.log(data[5]);     // check what's actually there

Sketch runs but exports are blank or wrong size

Missing pixelDensity(1). On Retina displays, p5 doubles the canvas resolution — your sketch looks fine on screen but exports at the wrong size. Always include: 

function setup() {
  createCanvas(825, 1275);
  pixelDensity(1); // ← required for correct exports
}

Common p5.riso Errors

Canvas is blank / Riso layers don't appear

Check that you're calling both clearRiso() and drawRiso() in the right order: 

function draw() {
  clearRiso();  // ← wipe layers at the start

  pink.fill(255);
  pink.circle(300, 400, 200);

  drawRiso();   // ← composite layers to the canvas at the end
}

If you forget drawRiso(), nothing appears on the canvas. If you forget clearRiso() in a looping sketch, layers accumulate and the image gets darker every frame.

Riso layer shows wrong color

The color name passed to new Riso() must exactly match a name in the RISOCOLORS array — all lowercase, no spaces. Check the homepage color chart for the exact string. 

// ✗ wrong — "Fluorescent Pink" is not a valid name
let pink = new Riso("Fluorescent Pink");

// ✓ correct
let pink = new Riso("fluorescentpink");

Riso fill has no effect

Riso layer fill takes a value from 0–255 controlling ink density, not a color. Setting it to 0 means no ink: 

pink.fill(0);   // no ink — nothing prints (probably not what you want)
pink.fill(255); // full density
pink.fill(128); // half density — lighter print

exportRiso() exports an empty frame

If you're calling exportRiso() before the sketch has drawn, or in a looping sketch between frames, the export will be blank. Use noLoop() and make sure you export only after drawRiso() has run: 

function keyReleased() {
  if (key === "e") {
    // safe — only runs after the current draw() completes
    exportRiso();
  }
}

Isolating Problems

When something is wrong and you can't tell why, comment out code until the sketch works, then add it back piece by piece: 

function draw() {
  clearRiso();

  pink.fill(255);
  pink.circle(300, 400, 150); // does this work alone?

  // blue.fill(180);           // comment this out temporarily
  // blue.rect(100, 200, 400, 300);

  drawRiso();
}

Start with the simplest version that should work, verify it does, then re-enable complexity one block at a time.
